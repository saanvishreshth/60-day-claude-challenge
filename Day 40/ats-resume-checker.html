The system prompt

The assistant is instructed to act as a professional ATS-and-recruiter reviewer speaking to a student or new grad, coaching-but-honest in tone. It must return strict JSON (no prose, no markdown fences) with an overall score, a plain-English summary, optional keyword match data if a job description was supplied, an array of annotations — each one an exact verbatim substring from the resume plus a category (fix / warn / good) and a short coaching comment — and a short list of top priority fixes.

Requiring verbatim substrings is the key design decision: it lets the frontend find-and-wrap the exact phrase in the original text with zero fuzzy matching, which is what makes the redline highlighting possible without a fragile NLP layer in the browser.

Edge cases are handled explicitly in the prompt: gibberish or non-resume text returns a polite low score with an explanation instead of hallucinated annotations; extremely short input asks for more content; and any attempt to make the assistant act outside resume review (jailbreaks, unrelated requests) is declined in-character, staying focused on the resume task.

Why the UI looks like this

The one output the user asked for was "line-by-line highlighted resume with inline comments" — so the whole interface is built around a single signature element: the resume rendered as a paper document with color-coded highlights, each one threaded to a margin comment card, mirroring how a human editor marks up a physical page. A generic score-gauge dashboard would have buried that. The score still appears, but as a small rotated stamp — a supporting detail, not the hero.

Palette and type stay editorial: warm paper tones, a serif for the resume "page," a plain sans for UI chrome, and three consistent semantic colors (fix / warn / good) used identically in the highlights, the margin cards, and the legend so the whole page reads as one coherent system.

Extending this

  • PDF/DOCX upload: currently accepts pasted text or plain .txt; add a parsing step (e.g. a PDF.js or mammoth.js call) before sending text to the API.
  • Memory across sessions: store previous reviews in localStorage keyed by resume hash, and show score-over-time as the user iterates.
  • Multi-step flow: chain a second Claude call that rewrites flagged bullets on request, turning this from a one-shot report into an editable back-and-forth.
  • Tool use: connect a job-board MCP/API so the user can paste a company name instead of the full job description, and the assistant fetches the posting itself.
