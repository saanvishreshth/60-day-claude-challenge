MODULE 01 / 04

Foundations: Functions & Scope

Before closures and decorators make sense, you need a rock-solid mental model of how Python looks up variable names. That model is called LEGB.

Explanation

A function in Python is a reusable block of code defined with def. Every time it runs, it gets its own private workspace called a local scope — a fresh dictionary of names that exists only while the function is executing.

When your code refers to a name (a variable), Python searches for it in a specific order, called the LEGB rule:

  • Local — names assigned inside the current function
  • Enclosing — names in any outer (non-global) function that contains this one
  • Global — names defined at the top level of the module
  • Built-in — names Python provides automatically, like len or print

Python stops at the first scope where it finds the name. This is why a local variable can "shadow" a global one with the same name.

Topic-Specific Example
def greet(name):
    greeting = "Hello"       # local variable
    return f"{greeting}, {name}!"

city = "Delhi"                # global variable

def describe():
    print(city)              # found in global scope

describe()  # Delhi
print(greet("Aria"))  # Hello, Aria!
print(greeting)

The last line raises NameError — greeting only exists inside greet's local scope and disappears once the function returns.

Analogy
Think of scopes as nested rooms in a house. A function call is like stepping into a room and closing the door. You can see furniture (variables) in that room, and you can peek through the doorway into the hallway (enclosing scope) and the front porch (global scope) if you don't find what you need — but people in the hallway can't see into your room after you leave it.
Diagram: The LEGB Search Path
Comparison

✗ Modifying a global by accident

count = 0
def increment():
    count = count + 1  # UnboundLocalError

Assigning to count anywhere in the function makes Python treat it as local for the whole function body — so reading it before assignment fails.

✓ Explicit with global

count = 0
def increment():
    global count
    count = count + 1  # works

The global keyword tells Python this name refers to the module-level variable, not a new local one.

Answer: 20. inner() has no local x, so Python checks the enclosing scope (outer's local x = 20) before the global x = 10. This enclosing lookup is exactly what makes closures possible, as you'll see in Module 3.

Common Misconceptions
"Python has block scope like C or JavaScript's let." False — if, for, and while blocks do NOT create a new scope in Python. Only functions (and modules, classes to a lesser extent) do.
"Reading a global variable inside a function requires the global keyword." False — you only need global when you plan to assign to that name inside the function. Reading works automatically via LEGB.
Key Takeaways
  • Every function call creates its own local scope that disappears when the function returns.
  • Name lookup follows Local → Enclosing → Global → Built-in, stopping at the first match.
  • Assigning to a name inside a function makes it local for that entire function unless declared global or nonlocal.
  • Blocks (if/for/while) don't create new scopes — only def does.

Functions as First-Class Citizens

In Python, functions are ordinary objects: you can assign them to variables, pass them as arguments, return them from other functions, and store them in data structures.

Explanation

"First-class" means a function has no special restrictions compared to any other value like an integer or string. Because of this, Python supports higher-order functions — functions that take other functions as arguments or return them as results.

A lambda is a small, unnamed function expression: lambda x: x * 2 is equivalent to a one-line def that returns x * 2. Lambdas can only contain a single expression, no statements.

Topic-Specific Example
def apply_twice(func, value):
    return func(func(value))

print(apply_twice(lambda x: x * 2, 3))   # 12

words = ["kiwi", "fig", "banana"]
words.sort(key=lambda w: len(w))
print(words)  # ['fig', 'kiwi', 'banana']

squares = list(map(lambda n: n**2, range(5)))
print(squares)  # [0, 1, 4, 9, 16]
Analogy
A function passed as an argument is like handing someone a recipe instead of a finished dish. apply_twice doesn't know or care what the recipe does — it just knows to run it, then run it again on the result. sort(key=...) works the same way: you hand it a "how to measure this item" recipe, and it does the sorting.
Diagram: Functions Flowing Through Higher-Order Functions
Comparison

Lambda

double = lambda x: x * 2

One expression only, no name required, great for short throwaway callbacks like sort keys.

    return x * 2

Supports multiple statements, docstrings, and a real name for tracebacks — prefer this for anything reused or non-trivial.

Common Misconceptions
"Lambdas are faster than regular functions." False — they compile to the same kind of function object; there's no performance difference. The only difference is syntax and that lambdas can't have statements or docstrings.
"You need lambda for any function passed as an argument." False — you can pass any existing named function directly, e.g. sorted(words, key=len). Lambda is just convenient for quick, unnamed logic.
Key Takeaways
  • Functions are objects: they can be assigned, passed, returned, and stored just like any value.
  • A higher-order function takes and/or returns other functions (map, filter, sorted(key=...)).
  • Lambda expressions are single-expression, unnamed functions — ideal for short, throwaway logic.
  • Prefer def over lambda once logic needs more than one line or a meaningful name.

Closures: Functions That Remember

A closure is a function that "remembers" variables from the scope it was defined in, even after that outer scope has finished executing. This is where the enclosing (E) in LEGB truly comes alive.

Explanation

When a nested function references a variable from its enclosing function, Python keeps that variable alive as part of the inner function's closure — a bundle of "free variables" attached to the function object. The enclosing function can even return, and the inner function still has access to that captured state.

To reassign (not just read) an enclosing variable from inside the nested function, you must declare it with nonlocal.

Topic-Specific Example
def make_counter():
    count = 0
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

counter_a = make_counter()
counter_b = make_counter()
print(counter_a())  # 1
print(counter_a())  # 2
print(counter_b())  # 1  (independent state!)
Analogy
A closure is like a backpack a function carries with it. When increment is created inside make_counter, it zips count into its backpack before leaving the "room." Every call to counter_a() reaches into that same backpack. counter_b got its own fresh backpack from a separate call to make_counter(), so the two never interfere.
Diagram: Closure Capturing State
Comparison

✗ The classic late-binding bug

funcs = []
for i in range(3):
    funcs.append(lambda: i)
print([f() for f in funcs])
# [2, 2, 2] — not [0, 1, 2]!

All three lambdas share the same enclosing variable i, and by the time they run, the loop has finished with i = 2.

✓ Fixed with a default argument

funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)
print([f() for f in funcs])
# [0, 1, 2]

The default value i=i is evaluated immediately, at definition time, capturing a snapshot instead of a live reference.

Common Misconceptions
"A closure copies the variable's value at creation time." False — it captures a reference to the variable itself. That's precisely why the loop/lambda bug above happens.
"Any nested function is a closure." Not quite — it's only meaningfully a closure once it actually references a free variable from an enclosing scope. A nested function using only its own locals isn't exhibiting closure behavior.
Key Takeaways
  • A closure is a function bundled with references to variables from its enclosing scope.
  • Use nonlocal to reassign (not just read) an enclosing variable.
  • Each call to the outer factory function creates independent captured state.
  • Closures capture variables by reference, which causes the classic loop-variable bug in lambdas.

MODULE 04 / 04

Decorators: Wrapping Behavior

A decorator is a closure applied to another function: it takes a function in, returns a new (usually wrapped) function out. The @ syntax is just sugar for calling that closure manually.

Explanation

A decorator is a higher-order function that accepts a function and returns a new function — typically one that calls the original plus does something extra (timing, logging, caching, access control). Inside, the wrapper commonly uses *args, **kwargs so it works with any function signature.

@decorator_name above a def is exactly equivalent to writing func = decorator_name(func) right after defining it.

functools.wraps preserves the original function's name and docstring on the wrapper, which is easy to lose otherwise.

Topic-Specific Example
import functools, time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} took {elapsed:.4f}s")
        return result
    return wrapper

@timer
def slow_square(n):
    time.sleep(0.1)
    return n * n

slow_square(4)  # prints: slow_square took 0.100xs
Analogy
A decorator is like gift wrapping. The original function is the gift inside; the wrapper is the wrapping paper around it. When someone "opens" (calls) the wrapped function, they first pass through the paper — where extra behavior can happen — before reaching the gift itself. The gift is unchanged, but the experience of calling it now includes the wrapping.
Diagram: How @decorator Rewires a Call
Comparison

✗ Decorator without functools.wraps

def wrapper(*a, **k):
    return func(*a, **k)
# slow_square.__name__ == "wrapper"
# original docstring lost

✓ With functools.wraps

@functools.wraps(func)
def wrapper(*a, **k):
    return func(*a, **k)
# slow_square.__name__ == "slow_square"
Practical Exercise
Try it

Write a decorator @repeat(3) — a decorator factory that takes an argument and makes the decorated function run 3 times. (Hint: you need three nested functions.)

def repeat(n):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def greet():
    print("hi")

Common Misconceptions
"Decorators can only be applied to functions." False — decorators can also wrap methods and even classes; the mechanism is identical (take an object, return an object).
"Stacking decorators is order-independent." False — @a above @b above def f applies b first, then a wraps the result: f = a(b(f)). Swapping the order can change behavior.
Key Takeaways
  • A decorator is a function that takes a function and returns a (usually wrapped) function.
  • The @decorator syntax is sugar for func = decorator(func).
  • Use *args, **kwargs in the wrapper to support any signature, and functools.wraps to preserve metadata.
  • Decorator factories (decorators that take arguments) need an extra level of nesting.
  • Stacked decorators apply bottom-up.

Final Practical Challenge
Capstone

Build a @memoize decorator using a closure that caches results of an expensive function in a dictionary, so repeated calls with the same arguments return instantly from the cache instead of recomputing.

Requirements: it must work with any positional-argument function, print whether a call was a cache hit or miss, and preserve the original function's name with functools.wraps.

import functools

def memoize(func):
    cache = {}
    @functools.wraps(func)
    def wrapper(*args):
        if args in cache:
            print(f"cache hit for {args}")
            return cache[args]
        print(f"cache miss for {args}")
        result = func(*args)
        cache[args] = result
        return result
    return wrapper

@memoize
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)

Summary Notes

Functions are objects that live in a scope. Scope lookup follows LEGB. When a nested function keeps a reference to a variable from an enclosing scope, that's a closure — the mechanism that lets factories like counters and multipliers produce independent, stateful functions. Decorators are simply closures applied to functions at definition time via @, letting you layer cross-cutting behavior (timing, logging, caching, access control) without touching the original function's code. Mastering these four ideas together — scope, first-class functions, closures, decorators — unlocks idiomatic, professional Python.
